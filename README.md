# Gate1 提出物

## 1. 起動手順

1. Google ドライブで空の Google スプレッドシートを新規作成する。
2. スプレッドシート上部の「拡張機能」→「Apps Script」を開く。
3. 最初から入っている `Code.gs` の内容をすべて削除する。
4. 提出物の `Code.gs` を開き、コード全文をApps Script側の `Code.gs` に貼り付ける。テキストファイルを開けない場合は、`Gate1_GAS_提出用.pdf` の2ページ目以降にあるコードを使用する。
5. 保存ボタンを押し、関数一覧から `setupGate1` を選んで「実行」を押す。
6. 初回のみ権限確認が表示されるので、自分のGoogleアカウントを選び許可する。
7. 「セットアップが完了しました」と表示されたら、スプレッドシートを再読み込みする。
8. メニューの「問い合わせ管理」→「問い合わせ詳細を開く」を選択する。

この実装はスプレッドシートに紐づく Apps Script として使用する。別のHTMLファイルは不要で、`Code.gs` だけで動作する。

## 2. 動作確認手順

### 2-1. 正常なステータス変更（NEW → IN_PROGRESS）

1. `setupGate1` 実行直後に「問い合わせ管理」→「問い合わせ詳細を開く」を選択する。
2. 問い合わせ1001が「未対応」、変更先が「対応中」だけになっていることを確認する。
3. 「ステータスを変更」を押す。この操作は `NEW → IN_PROGRESS` に対応する。
4. 「ステータスを「対応中」に変更しました。」が緑色で表示されることを確認する。
5. 担当者が操作者の「佐藤 花子」になり、変更履歴にステータスと担当者の2件が追加されることを確認する。

### 2-2. 不正遷移エラー（NEW → DONE）

1. 先に `setupGate1` をもう一度実行し、データを初期状態へ戻す。
2. 「問い合わせ管理」→「提出用モック」→「不正遷移エラーを表示」を選択する。
3. サーバー側へ許可されていない `NEW → DONE` が送信される。
4. 「このステータスへは変更できません。画面を再読み込みしてください。」が赤色で表示されることを確認する。
5. `inquiries` シートで、問い合わせ1001のステータスが `NEW` のまま、担当者と `updated_at` も変更されていないことを確認する。

### 2-3. DONEからの再オープン（DONE → IN_PROGRESS）

1. 「問い合わせ管理」→「問い合わせIDを変更する」で `1002` を入力する。
2. 現在が「完了」、変更先が「対応中」だけであることを確認する。
3. 「ステータスを変更」を押し、「ステータスを「対応中」に変更しました。」が緑色で表示されることを確認する。
4. `inquiries` シートで、問い合わせ1002のステータスが `IN_PROGRESS` になり、`closed_at` が空欄になったことを確認する。
5. 変更履歴に「ステータス：完了 → 対応中」が1件追加されたことを確認する。

### 2-4. MEMBER権限

1. `setupGate1` で初期状態へ戻す。
2. 「操作ユーザーを変更する」で `2`（山田 太郎 / MEMBER）を指定する。
3. 問い合わせ1001では自分への割り当てが成功することを確認する。
4. 担当者設定後は担当者変更ボタンが非活性になり、「担当者の変更は管理者に依頼してください」と表示されることを確認する。
5. 権限判定は `changeAssignee` 内でも再実行され、画面を改変して送信しても拒否される。

### 2-5. 履歴失敗時のロールバック

1. `setupGate1` で初期状態へ戻す。
2. 「問い合わせ管理」→「テスト用」→「次の履歴登録を失敗させる」を選択する。
3. 問い合わせ1001を「対応中」へ変更する。
4. 「履歴登録が失敗したため、本体の更新も元に戻しました。」と表示されることを確認する。
5. `inquiries` のステータス・担当者・更新日時が変更前のままで、`inquiry_histories` に行が増えていないことを確認する。

## 3. 実装できなかった箇所

なし。

Googleスプレッドシートには一般的なRDBのトランザクション機能がないため、N-01はドキュメントロック、更新前スナップショット、例外時の問い合わせ行復元と追加履歴クリアを組み合わせて実装した。更新と履歴登録の間で失敗しても、利用者から見たデータは変更前へ戻る。

## 6. 振り返り

### 6-1. 実装前に判断に迷った箇所はありましたか。あったなら、それは仕様書のどこが不足していたからですか。

大きく判断に迷う箇所はなかった。状態遷移表、付随処理、担当者権限、表示条件、メッセージ、排他制御まで定義されていたためである。GoogleスプレッドシートにRDBのトランザクションがない点だけ実装方法の選択が必要だったが、仕様の目的を満たすようにロックとロールバックで対応した。

### 6-2. 最初のAIプロンプトを見返して、要件定義書のどの部分を伝え忘れましたか。

最初の指示文だけでは、状態遷移表、R-01〜R-06、V-01〜V-07、9種類のメッセージ、排他制御、履歴失敗時のロールバック、モック画像、README、プロンプトログの条件を具体的に書いていなかった。今回は添付された要件定義書をAIへ渡していたため、そこから不足情報を補えた。
